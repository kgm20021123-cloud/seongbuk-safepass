# 배포 가이드 — 깃허브 · Vercel 연결

우리 폴더(`team_project`)를 깃허브에 올리고, Vercel 이 그것을 인터넷 주소로 열어 준다.
**관리 담당 한 명이 자기 노트북에서** 처음부터 끝까지 한다.

## 0. 준비

| 무엇 | 어떻게 |
|---|---|
| 작업 위치 | Claude Code 를 `team_project` 폴더에서 연다(데스크톱은 Code 탭에서 작업 폴더로 `team_project` 를 고른다). `web` 같은 하위 폴더를 따로 만들지 않는다 |
| 브라우저 | 깃허브 · Vercel 은 처음부터 끝까지 **한 브라우저에서만** 한다. 그 브라우저의 깃허브 계정이 `gh auth status` 에 나온 계정과 같은지 먼저 본다 |
| 깃허브 계정 | github.com 에서 가입 — **개인 계정**으로 한다 |
| Vercel 계정 | vercel.com 에서 가입할 때 **GitHub 로 가입**을 고른다 |
| 확인 | `.env` 에 키가 들어 있고, `.gitignore` 에 `.env` 줄이 있다 |

## 1. gh 설치 · 로그인 (처음 한 번)

`gh` 는 깃허브를 터미널에서 다루는 프로그램이다.

| 컴퓨터 | 설치 명령 |
|---|---|
| macOS | `brew install gh` — `brew` 가 없다고 나오면 brew.sh 에서 Homebrew 부터 설치한다 |
| Windows | `winget install --id GitHub.cli --source winget` — 설치 후 **Claude Code 를 껐다 다시** 연다 |

데스크톱 **Terminal**(제목줄 Terminal 또는 Ctrl+`)에서 친다.

```
gh auth login
```

- 물음은 Enter 로 기본값을 고른다(GitHub.com · HTTPS · 브라우저 로그인)
- 화면에 나온 코드를 브라우저 창에 넣고 허용한다

## 2. 깃허브에 올리기 (처음 한 번)

`team_project` 에서 연 Claude 에게 붙여 넣는다.

```
이 폴더를 내 깃허브에 공개(public) 저장소로 올려 줘.

[먼저]
올라갈 파일 목록을 보여 주고, .env · 키 · 개인정보가 든 문서가 없는지 확인한다 — 공개 저장소라 누구나 본다.
git 커밋 이름 · 이메일이 없으면 나에게 물어 이 폴더에만 설정한다 — 이메일은 깃허브 계정 이메일로.

[순서]
git init → 첫 커밋 → gh repo create <팀이름> --public --source=. --push

[하지 말 것]
.env 를 올리지 않는다.
```

- `<팀이름>` 은 영어 · 숫자 · `-` 로 바꿔 넣는다 (예: `team3-chatbot`)
- 끝나면 github.com 에서 저장소를 열어 **`.env` 가 없는지** 눈으로 본다

## 3. Vercel 연결 (처음 한 번)

| 순서 | 화면에서 할 일 |
|---|---|
| ① | vercel.com 로그인 → **New Project** |
| ② | 깃허브 저장소 목록에서 우리 저장소 → **Import**. 저장소 이름 옆에 **`main`** 이 보이면 준비된 것이다 (안 보이면 아래 「저장소가 목록에 안 보이면」) |
| ③ | Framework Preset — **Other** (화면은 `public` 폴더가 나간다) |
| ④ | Root Directory — **그대로** (`./`) |
| ⑤ | Environment Variables — 접혀 있으면 `>` 를 눌러 펼친다. **Import .env** 를 눌러 `.env` 파일을 고른다 (Mac 파일 창에서는 **Cmd + Shift + .** 을 눌러야 `.env` 가 보인다). 이름이 `.env` 와 같은지 본다 — `GROQ_API_KEYS` · `GEMINI_API_KEYS` 는 **끝의 S 까지** |
| ⑥ | **Deploy** → 이메일 코드를 물으면(Reauthenticate) 메일로 온 6자리를 같은 브라우저에 넣고 **Verify** → 끝나면 Deploy 끝 화면에 나온 주소를 연다 |

### 저장소가 목록에 안 보이면

「No Results Found」가 나오면 Vercel 이 그 저장소를 읽을 권한이 없는 것이다.

1. 같은 브라우저에서 깃허브 → **Settings → Applications → Vercel → Configure** 를 연다
2. Repository access 의 **Select repositories** 에서 우리 저장소를 추가하고 **Save** 를 누른다
3. 그래도 목록에 없으면 주소창에 `https://vercel.com/new/import?s=https://github.com/《계정》/《저장소 이름》` 을 연다

저장소 이름 옆이 `main` 이 아니라 `…` 이면 아직 권한이 없다 — 그대로 Deploy 하면 「couldn't be found」 오류가 난다.

## 4. 고친 뒤

Claude 에게 「바뀐 것 커밋하고 깃허브에 올려 줘」라고 하면 Vercel 이 **알아서 다시 배포**한다.
키를 바꿨으면 Vercel 의 Environment Variables 도 같이 고치고 다시 배포한다.

## 5. 주의

| 무엇 | 왜 |
|---|---|
| 공개 저장소 | 누구나 코드 · `docs` 를 본다 — 올리기 전에 파일 목록을 다시 본다(`.env` · 키 · 개인정보 문서는 올리지 않는다) |
| `.env` 는 절대 올리지 않는다 | 한 번 올라간 키는 지워도 기록에 남는다 — 그때는 키를 새로 받는다 |
| 서버가 읽는 폴더 | `vercel.json` 의 `includeFiles` 에 넣는다 — `docs/**`, 서버가 조각을 읽으면 `chunks/**` 도(`chunks` 는 `docs` 밖에 있다). 안 넣으면 배포본에서만 「모른다」가 나온다 |
| Root Directory 를 하위 폴더로 바꾸지 않는다 | 그 폴더 밖의 파일(`docs/답변참고문서` 등)에 서버가 닿지 못한다 |
